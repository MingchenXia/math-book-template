# Revising a completed book

This procedure follows [SGPT's AGENTS.md](https://github.com/MingchenXia/SGPT/blob/main/AGENTS.md): mathematical revisions require reviewable branches and PRs, and author approval is separate from agent review. The generic template does not hard-code SGPT's personal website or manuscript style.

1. **Record completion.** After a full current review, run `make finish`. It rebuilds the PDF, records source/PDF fingerprints and the resolved-problem baseline, creates the revision queue and sets phase to revision. Update STATUS and CHANGELOG, then commit the baseline to main. This starts the completed-book revision procedure; it does not establish that every problem is solved.
2. **Start a proposal.** Preserve existing changes and synchronize main with `git pull --ff-only`. Run `python3 scripts/bookflow.py revision-start fix-estimate`. It requires a clean working tree on main and creates `revision/fix-estimate`, without copying uncommitted changes or forcibly resetting branches.
3. **Make the complete correction.** Reconstruct the dependency chain before changing definitions, hypotheses, statements, proofs, examples or calculations. Check prerequisite results and every affected later use. Record actual changes; reading a correct passage without altering it is not a correction. In `revision-queue.json`, move the unit through pending, editing, reviewed and author_pending, recording actual scope and reports in notes. Cover recursive inputs, transitions, figures and sources. Use `make edit` for the writing/editor agent.
4. **Review and prepare PDFs.** `make review` builds the manuscript and starts independent read-only review. Repair substantive findings and request another review. Run `python3 scripts/bookflow.py revision-prepare --base main --pages 12-15,29 --summary "Describe the substantive correction"`. Pages are physical PDF numbers and must cover every modified passage with context. The command retains the full PDF, extracts selected pages, and prepares a diff, proposal record awaiting author approval and PR text. Inspect excerpt coverage and attach a before PDF if needed; extraction cannot detect omitted modified pages. Preserve any required baseline style and TeX engine.
5. **Open a PR.** Inspect the diff and file list; commit complete source changes, actual CHANGELOG entries and proposal records. PDFs under `build/` remain outside source commits. Push the proposal and use the prepared body file:

   ```sh
   git add book bookflow.json research references/references.bib CHANGELOG.md
   git diff --cached
   git commit -m "Explain the substantive correction"
   git push -u origin revision/fix-estimate
   gh pr create --base main --head revision/fix-estimate --title "Explain the substantive correction" --body-file build/revision/fix-estimate-pr.md
   ```

   Link the PR and a clickable PDF excerpt in the Codex chat. After creating a PR through Codex tools, call attach_artifact. Other collaborators can download this PR's `Book checks` artifact for the matching full PDF; its manifest binds the current source. Identify affected chapters, explain the correction and record uncertainties. Verify uploaded PDFs correspond to the current proposal.
6. **Obtain author approval of this version.** The author must explicitly approve the current PR and PDF. Record the approved revision/source fingerprint and evidence in the PR discussion or controlled publication record. Agent approval, successful CI, silence and approval of an earlier version do not authorize merge. After a substantive change, provide a new PDF and obtain renewed approval. Queue bookkeeping does not substitute for it.
7. **Merge and publish.** Under the author's current authorization, merge the approved PR, synchronize main and verify the merged source fingerprint matches the approved version. Rebuild and inspect the PDF. The template provides CI PDF artifacts without automatic website publication. Choose the publication destination and version naming before publishing within authorization. If publication is deferred, retain local/CI PDFs. Verify any website deployment separately.
8. **Clean up and continue.** Confirm the PR is merged and its remote proposal branch has been deleted, optionally with GitHub's automatic deletion setting. Switch to synchronized main, check for unmerged work and use `git branch -d revision/fix-estimate`. Do not use `-D` to discard unmerged work. Mark the unit completed and identify the next unit in STATUS. Completing one chapter is not completion of the whole book.

The commit hook blocks book/solution/reference source commits on non-revision branches after completion. This collaboration guard can be bypassed; use main branch protection, required PRs and author review as appropriate. Catalogue/review maintenance PRs do not authorize merging mathematical proposals.
