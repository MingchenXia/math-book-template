# Writing environment

Codex Cloud uses a [separate setup flow](codex-cloud.md). Run `bash scripts/setup-codex-cloud.sh` to install the repository's system packages; review the verification report and publish the environment in the cloud interface. It does not automatically read the Dev Container configuration. Hosted agents can write directly and organize independent review through assignment export and report registration, without copying a personal CLI login into the environment.

For Codespaces or VS Code, use **Dev Containers: Reopen in Container**. `.devcontainer/Dockerfile` installs Node 22, Python, TeX, Biber, MakeIndex, Poppler and `@openai/codex@0.157.1`. The container runs as an ordinary user and contains no login credentials. Initial startup performs setup and compiles the example. See [GitHub's Dev Container documentation](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/introduction-to-dev-containers).

`bash start.sh` first uses installed local tools; if tools are missing, it builds the same environment with Docker. It prepares and compiles the book without creating a cloud service or signing into an account. Command-mode Docker containers exit when the command finishes; use Dev Containers for a full editing session. The base image and Debian packages use maintained version labels, and the Codex CLI version is pinned. This is a reproducible tool configuration, not a byte-for-byte locked system image.

On macOS, an existing MacTeX installation is sufficient. On Debian, use Docker or install the packages listed in the Dockerfile's package manifest. `make doctor` checks commands and TeX files. The English demonstration uses pdfLaTeX. If another engine is required, change `engine` in `bookflow.json` to `xelatex` or `lualatex` and adapt the class and font setup accordingly. The container also includes CJK fonts and ctex. Keep theorem and bibliography settings consistent.

Local agents use `codex login` and your configured default model. GitHub Actions uses secret `OPENAI_API_KEY` with `codex login --with-api-key` in a temporary container. Login writes to the user's configuration directory, outside Git. CLI arguments were checked against `codex exec --help`; structured reviews use `--output-schema`. See the [official CLI reference](https://developers.openai.com/codex/cli/reference).

BibTeX is the default bibliography backend for compatibility with existing installations. To use Biber, set `bibliography_backend` to `biber` and ensure the matching executable is available. The container includes both. Backend changes clear the old generated cache without weakening TeX's file-write restrictions. If a desktop-configured model name is unsupported by the separate CLI account, run `BOOKFLOW_CLI_DEFAULTS=1 make review`. This invocation uses CLI defaults, retains login and does not change global configuration.

`scripts/setup.sh` registers this repository's `.githooks` to synchronize the catalogue and check revision branches before commits. Merge these hooks with any existing custom hooks first. Restore the default with `git config --unset core.hooksPath`. Do not run setup on a parent repository containing a nested book checkout.

PDFs and excerpts are generated under `build/`. LaTeX Workshop automatic building is disabled because `make build` must first update generated TeX. Use the **Book: build PDF** VS Code task. `build/build-manifest.json` records the relationship between source and PDF.
